## 输入

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `target_ic` | float | `0.04` | 目标 IC（信息系数）。IC ≥ target_ic 才算成功 |
| `category` | str | `"momentum"` | 因子类别: `momentum` / `value` / `quality` / `volatility` / `custom` |
| `budget` | float | `5.0` | 本次调用的预算上限 (USD)。**不能超过** Hermes config 的 `budget.max_cost_per_session` |
| `max_iterations` | int | `30` | 本次调用的最大迭代次数。**不能超过** Hermes config 的 `budget.max_iterations` (session-wide cap = 50) |
| `start_date` | str | `"2022-01-01"` | 因子评估 + 回测窗口起始日 (YYYY-MM-DD) |
| `end_date` | str | `"2024-01-01"` | 因子评估 + 回测窗口终止日 (YYYY-MM-DD) |
| `symbols` | []string | `["000001.SZ", "600000.SH", ...]` | 股票池。空数组则使用默认沪深 300 成分股前 50 |

> **Two-layer budget distinction**:
> - **Skill input `max_iterations` (default 30)**: per-invocation soft default. 保守于 session cap，留出 headroom 给其他 skill。
> - **Hermes config `budget.max_iterations` (default 50)**: session-wide hard cap. 即使 skill 传入更大的值，Hermes 也会用 session cap 截断。

## 循环体

### Step 1: 查询已有因子 + 系谱路径 + 市场状态（避免重复挖掘）

```
# 1a. 查询已有因子
list_factors(category=$category, min_ic=$target_ic * 0.8)
  → 记录已有公式集合 existing_formulas = {...}
  → 记录 top 1-2 策略的 strategy_id

# 1b. 查询系谱路径（反思机制 — 了解已有变体路径，避免重挖相似变体）
for strategy_id in top_strategy_ids:
  get_strategy_lineage(strategy_id=$strategy_id, max_depth=3)
    → 记录祖先链 + 变异历史 → 已探索的变异维度 explored_dims = {...}

# 1c. 查询市场状态（市场环境判断 — 牛市偏向动量，熊市偏向防御，震荡偏向均值回归）
get_market_regime(start_date=$start_date, end_date=$end_date)
  → trend: "bull" | "bear" | "sideways"
  → volatility: "low" | "medium" | "high"
  → sentiment: float [-1.0, 1.0]
  → 记录 market_context = {trend, volatility, sentiment}
```

### Step 2: 生成因子假设

```
LLM 推理:
  输入: DSL 语法 + existing_formulas + explored_dims + market_context + 市场知识
  输出: factor_expression = "<DSL 字符串>"

约束:
  - 表达式必须用 DSL 语法（不生成 Go 代码）
  - 必须避开 existing_formulas（避免重复）
  - 必须避开 explored_dims（避免重挖相似变体）
  - 根据 market_context 选择因子方向:
    * bull + low volatility  → 动量类因子 (ts_rank, ts_delta)
    * bear + high volatility  → 防御类因子 (ts_min, 反转动量)
    * sideways               → 均值回归类 (cs_rank, cs_zscore)
```

### Step 3: L1 验证 — 语法门禁

```
validate_factor(expression=$factor_expression)
  → {valid: true/false, inputs: [...], ast: "...", gate_decision: {level, passed, reason, recommendation}}

失败处理:
  - 收到错误信息 → 修正表达式（语法/字段/函数名）→ 回到 Step 2
  - 连续 3 次 L1 失败 → 放弃当前假设方向 → 回到 Step 2 重新生成
```

### Step 4: L2 快速 IC — 信息系数字门禁

```
compute_factor_ic(
  expression=$factor_expression,
  start_date=$start_date,
  end_date=$end_date,
  symbols=$symbols
)
  → {ic: float, ir: float, turnover: float, decay: [...], gate_decision: {level, passed, reason, recommendation}}

决策点 (per IC 范围):
  - IC > 0.05       → 优秀因子，立即进入 Step 5
  - 0.02 < IC ≤ 0.05 → 有意义，尝试 2-3 个变体（改窗口/字段）后决定
  - IC < 0.02       → 放弃，换方向 → 回到 Step 2
  - IC ≥ $target_ic → 继续 Step 5
```

### Step 5: 生成策略 YAML

```
构建 ExpressionStrategy YAML:

strategy:
  name: <auto-generated-name>      # e.g. momentum_20d_v3
  type: expression
expression:
  signal:
    expression: "$factor_expression"
    direction: long                # long | short (per market_context)
  sizing:
    method: equal                  # equal | strength_prop | fixed
    max_per_stock: 0.10
  risk:
    max_open_positions: 20
    stop_loss: 0.08                # 根据 volatility 调整:
                                    #   high → 0.06, medium → 0.08, low → 0.10

约束:
  - 根据 market_context 调整 risk 参数:
    * volatility=high  → 减仓 (max_per_stock=0.05, stop_loss=0.06)
    * volatility=low   → 加仓 (max_per_stock=0.12, stop_loss=0.10)
  - trend=bear → direction=short 或 max_open_positions=10 (防御)
```

### Step 6: L3 标准回测 — 策略门禁

```
backtest.run(
  strategy_name=<yaml 中的 name>,
  stock_pool=$symbols,
  start_date=$start_date,
  end_date=$end_date
)
  → result_json (full BacktestResult)

summarize_backtest(result_json=$result_json)
  → {total_return, sharpe, max_drawdown, win_rate, risk_level, risk_warnings, gate_decision: {level, passed, reason, recommendation}}

决策点 (per Sharpe 范围):
  - Sharpe > 1.0  → 强策略，立即进入 Step 7
  - 0.5 ≤ Sharpe ≤ 1.0 → 可接受，进入 Step 7
  - Sharpe < 0.5  → 分析 risk_warnings → 修正策略（sizing/risk）→ 回到 Step 5
  - Sharpe < 0.3  → 放弃，重新设计 → 回到 Step 2
```

### Step 7: L4 Walk-Forward — 过拟合检测门禁

```
walk_forward_validate(
  strategy_name=<yaml 中的 name>,
  stock_pool=$symbols,
  start_date=$start_date,
  end_date=$end_date
)
  → {avg_test_sharpe, avg_degradation, per_window: [...], gate_decision: {level, passed, reason, recommendation}}

决策点 (per degradation 范围):
  - degradation ≥ 0.70  → 低过拟合，通过 L4 ✓ → 进入 Step 8
  - 0.50 ≤ degradation < 0.70 → 中等过拟合，记录但可保存 → 进入 Step 8
  - degradation < 0.50  → 高过拟合，**必须放弃** → 回到 Step 2
```

### Step 8: 保存到基因池

```
# 8a. 保存因子
save_factor(
  name=<factor-name>,           # e.g. "price_momentum_20d"
  category=$category,
  formula=$factor_expression,
  description="<LLM 生成的因子描述>",
  rationale="<经济理性说明>",
  ic=<from Step 4>,
  turnover=<from Step 4>,
  sharpe=<from Step 6>
)
  → factor_id = "fg_<uuid>"

# 8b. 保存策略
save_strategy(
  name=<strategy-name>,
  strategy_yaml=<YAML 字符串>,
  factor_ids=[factor_id],
  sharpe=<from Step 6>,
  max_drawdown=<from Step 6>,
  total_return=<from Step 6>
)
  → strategy_id = "sg_<uuid>"

幂等性保证:
  - save_factor / save_strategy 使用 UPSERT (ON CONFLICT)
  - 重复调用安全 — Hermes 可在不确定是否已保存时重试
```

### Step 9: 反思（Reflection — 为下一轮提供上下文）

```
# 9a. 查询新保存策略的系谱
get_strategy_lineage(strategy_id=$strategy_id, max_depth=3)
  → 祖先链 + 变异历史

# 9b. 分析改进点
LLM 反思:
  - 此策略相对于其父策略的改进点是什么？
  - 哪些维度还没探索？(窗口/字段/方向/sizing/risk)
  - 结合 market_context 分析: 策略在什么市场环境下表现好？
  - 是否需要为不同 regime 设计变体？

# 9c. 输出反思结果到 memory
  → trajectory.append({strategy_id, factor_expression, ic, sharpe, degradation,
                       market_context, reflection_notes})
```

### Step 10: 检查终止条件

```
检查以下条件（按优先级）:

1. 成功 (SUCCESS):
   - 因子 IC ≥ $target_ic ✓
   - 通过 L4 (degradation ≥ 0.50) ✓
   - 已保存到基因池 ✓
   → 返回: {status: "success", factor_id, strategy_id, ic, sharpe, degradation}

2. 预算耗尽 (BUDGET_EXHAUSTED):
   - cost ≥ $budget
   → 返回当前最佳: {status: "budget_exhausted", best_factor, best_ic, cost}

3. 迭代上限 (ITERATION_LIMIT):
   - iterations ≥ $max_iterations
   → 返回当前最佳: {status: "iteration_limit", best_factor, best_ic, iterations}

4. 收敛停滞 (CONVERGENCE_STALL):
   - 连续 5 轮无 IC 改善 (best_ic 未更新)
   → 返回当前最佳: {status: "convergence_stall", best_factor, best_ic, stall_count}

5. 以上均不满足 → 回到 Step 2 开始下一轮
```

## 终止条件汇总

| 条件 | 判定 | 返回 |
|------|------|------|
| 成功 | IC ≥ target 且 degradation ≥ 0.50 且已保存 | `status=success` + 完整结果 |
| 预算耗尽 | `cost ≥ budget` | `status=budget_exhausted` + 当前最佳 |
| 迭代上限 | `iterations ≥ max_iterations` | `status=iteration_limit` + 当前最佳 |
| 收敛停滞 | 连续 5 轮 best_ic 无改善 | `status=convergence_stall` + 当前最佳 |

## 预算控制契约

本 Skill 的预算控制由 Hermes 端的 `ResearchBudget` 控制器（见 [hermes.yaml](../config/hermes.yaml)）执行：

```
cost_model:
  ollama_local:    $0.00           # 本地部署不计费
  together_8b:      $0.0002 / 1K tokens  # (tokens_in + tokens_out) / 1000 * 0.0002
  together_70b:     $0.0006 / 1K tokens  # 可选 — 高质量模式

每次 LLM 调用后:
  cost += (tokens_in + tokens_out) / 1000 * rate
  llm_calls += 1
  iterations += 1

每次工具调用前检查:
  if not budget_controller.can_continue():
    → 触发终止条件 (预算耗尽或迭代上限)
```

## 验收标准

> **来源**: System Design §11 Phase 2 验收

给定输入 `{target_ic: 0.04, category: "momentum", budget: 2.0, max_iterations: 20}`，Hermes 在 $2 预算内：

1. 调用 `list_factors` 查询已有动量因子
2. 调用 `get_market_regime` 获取市场状态
3. 调用 `validate_factor` (L1) 至少 1 次
4. 调用 `compute_factor_ic` (L2) 至少 1 次
5. 如果 IC ≥ 0.04：调用 `backtest.run` (L3) + `summarize_backtest`
6. 如果 Sharpe ≥ 0.5：调用 `walk_forward_validate` (L4)
7. 如果 degradation ≥ 0.50：调用 `save_factor` + `save_strategy` 保存
8. 调用 `get_strategy_lineage` 进行反思
9. 在 `cost < $2` 或 `iterations < 20` 内完成
10. 返回结构化结果（status + factor_id + strategy_id 或 best_factor）
